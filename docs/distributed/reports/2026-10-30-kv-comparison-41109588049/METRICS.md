## Coverage and definitions

Matrix and comparison each contain 196 distinct matching case IDs, all 196 completed; 196 observed operation/outcome populations, 1,271,808 successful measured calls, 0 rejected and 0 other errors. No synthetic qualification-only rows are included. Each CSV/JSON row links its exact case receipt and raw samples; all 196 measurement sample populations were independently read and their nearest-rank quantiles checked against the source export. Timing fields are nanoseconds; CSV blanks / JSON null mean unavailable, not zero.

API, response and scheduling statistics are per operation/outcome conditional populations, not pooled across operations. The export provides sample counts, p50/p95/p99/p999, mean, population standard deviation and maximum for each clock; nearest-rank quantile is sorted observation at ceil(p × n). Within-case standard deviation is not run-to-run variation. All populations have fewer than 10,000 calls, so p99 is descriptive; all have fewer than 100,000, so p999 is descriptive and tails are sparsely sampled. Throughput denominators are observed exposure from earliest measurement scheduled timestamp to latest measurement completion, including failed/rejected arrivals if present; calls/s is successful API calls, keys/s counts successful logical keys, MiB/s is successful payload bytes / 2²⁰. Batch calls/s is not keys/s. Response includes scheduling; clocks/stages can overlap and percentiles cannot be added or subtracted to infer pure network or device time.

## Semantics and cache boundaries

- Native is in-process; explicit Value-WAL persistence barrier on writes. Its ordered get-many loops over scalar `Db::get`; its local reads are not network reads.
- TideHunter distributed primary has configured coordinator and owner explicit caches zero; Linux page cache is not controlled or verified by the primary adapter. Acknowledgement is RF1 owner complete Value-WAL batch persistence; crash-recovery batch scope is not serializable visibility/isolation. TCP, EFA and EFA-direct report mutual TLS; EFA-native reports trusted-network/no TLS. Tier experiments configure different caches and need their own qualification evidence.
- Valkey serves its dataset from RAM, not a disk-read-equivalent KV path; observed `appendonly=yes`, `appendfsync=always`, `no-appendfsync-on-rewrite=no`, no replica acknowledgement. Authentication disabled and TLS not configured. MGET is split by cluster slot and results reordered.
- TiKV RawKV is nontransactional, native batch_get, RF1 and plaintext; acknowledgement is server-defined and physical fsync was not independently verified. Cassandra uses CQL Quorum at observed RF1, `durable_writes=true`, plaintext, no verified commitlog fsync policy or physical persistence; get-many is bounded per-key query fanout, not native batch GET.
- FoundationDB uses transaction commit and serializable transaction semantics, but the adapter implements read-many as **sequential gets in one transaction**, not native parallel batch GET. Its physical-device fsync and effective TLS/authentication were not independently verified.
