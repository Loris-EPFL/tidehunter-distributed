1     Scope and findings
This brief reports measured key–value workloads and separate Sui value sizes, not Sui replay performance. Runs 9
and 10 add separate compact two-VM read/write and fabric A/B campaigns; earlier fleets remain separate.
Closed-loop concurrency c counts workers that wait for one call before starting the next (c1, c5, c16). A route
connects caller and value. An owner holds one shard’s Value WAL; the coordinator holds the distributed index
and publishes completed writes. Native runs in process, without a coordinator or network hop.

2     Acknowledgement contracts
The original Tidehunter paper, arXiv:2602.01873v2, Section 3.1, states: “Writes complete without waiting for fsync”. Its
page-cache acknowledgement survives an application crash, not an immediate kernel crash or power loss. Background fsync
provides eventual kernel-crash durability; explicit flush supports stronger needs. wal_replay selects recovery history, not
the acknowledgement contract.
Binding classes. The new plan uses S, P and W. Retained figures use Class B for S and Class A for P; their values do
not change.

                                                        always; Kvrocks synced WAL; Garnet commit-wait. Cassandra,

yet. S is the cross-store headline; P is the Sui-contract comparison; W is weaker context beside P, never a ranking. Reads

3    Method and contracts
API time is completion minus dispatch. Response time is completion minus schedule time in the closed-loop
harness; it includes scheduling and admission. Latency uses successful calls only. Rejected calls have no API
latency. Quantiles use exact nearest rank within each operation and outcome. No samples or fleets are pooled. A
median across runs is a median of per-run statistics, not a quantile of pooled calls. A range is minimum to
maximum, not a confidence interval. One profiled repetition gives no confidence interval or significance claim.

    Backend and tier             Acknowledgement contract
    Native value_wal_barrier     Class B: fsync of the Value-WAL files and the directory after every put.
    Native page_cache            Class A: returns after the page-cache write. Does not wait for fsync.
    Native grouped barrier       Class B: shared covering Native file/directory barrier; not per-put sync.
    Owner synchronous            Class B: returns after the covering Value-WAL fdatasync. Several puts can share
                                 it.
    Owner native                 Class A: page-cache acknowledgement. This tier has no relation to the native
                                 backend.


The paper’s default acknowledgement does not wait for fsync (Section 3.1, Durability Guarantees). Our native
barrier tier is stricter. It matches the durable intent of owner synchronous and Valkey AOF
appendfsync=always; it is not the paper’s latency contract.

          Instrument        Meaning and exactness
          Write timeline    Exact intervals between adjacent coordinator events of a retained call. Their
                            averages are sampled aggregates. Owner and coordinator timestamps are not
                            subtracted. Shared owner envelopes prevent an additive owner/network split at
                            c16.
          Write profile     Sampled means with stage-specific counts. Native scalar puts and deletes have
                            profiles; native batches do not. Native “coordinator” means library insert work:
                            WAL append plus index update.
          Read profile      Sampled stage means. Some residuals are differences of means with equal counts
                            but unproved population identity. They are estimates, not exact per-call partitions.
                            c16 profiles do not cover all reads.
          Floors            Standalone network round trips or queue-depth-one (QD1) I/O controls. Perftest
                            ib_send_lat and ib_write_lat record half round trips; tables and plots double
                            both. ib_read_lat already records round trips. No floor is subtracted to invent a
                            stage.
          Device counters   Window-wide block-device observations, not call-linked physical service measure-
                            ments. SPDK bdev counters observe its submitted reads.


Device-counter correction (one definition for this brief). /proc/diskstats deltas cover the gate-to-gate
window (3–10 s), while a case runs 0.5–2 s. They include background writeback of dirty owner history files: about
15 KiB dirtied per put; idle owners still wrote 13–15 operations/s of 41–45 KiB. A per-operation device latency
from these counters is not valid for a native-versus-owner write comparison. Use the system call timed inside each
system. A pre-window sync and dirty-page drain is a future controller change, not a property of run 8.
Security and routes (runs 7–9). TCP owner RPC uses mutual TLS (mTLS). Owner verbs and both hybrid
arms use trusted transport without TLS. Run 8 verbs mTLS isolates the security choice.
TCP-versus-trusted-verbs includes TLS, not just transport. Hybrid reads use NVMe over Fabrics (NVMe-oF)
over RDMA, with the kernel initiator. The kernel buffered target serves memory; kernel direct and SPDK file
AIO bypass the target page cache. Both hybrid write routes use owner verbs. Replication factor one (RF1)
means one durable owner, not failover.
Run-9 compact topology. Two z4m-highmem-16 VMs: Native uses the coordinator SSD, owner RPC the
remote owner SSD; coordinator cache off. Native has zero remote-read lanes, owners one at c1/c5 and four at c16.
c5 owner reads are lane-limited, not a transport ranking (Section 6).
Run-10 arms. Warm owner reads separate TCP mutual TLS Adaptive, TCP trusted Adaptive/Busy and verbs
trusted Adaptive/Busy. Cold owner RPC is compared with direct kernel NVMe/RDMA, SPDK NVMe/RDMA
and kernel NVMe/TCP. Busy spins in user space on both owner and coordinator; it is not kernel busy poll. Full
contracts and run-9 security correction are in Section 7.
Not measured in runs 7 and 8. Native read decomposition; batch reads; unprofiled batch components on
TCP and hybrid; deletes on hybrid and verbs mTLS. Profiled copies carry profiling cost. The appendix separates
profiles from controls. “n/c” means not computed, never zero.

separate.
