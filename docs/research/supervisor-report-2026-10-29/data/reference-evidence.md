## Comparison restrictions and unresolved evidence

* Latest campaign is synthetic, not checkpoint replay; one independent repetition per case. Within-case percentiles are not repeated-run confidence intervals. Native control is this fork, not independently pristine upstream. Warm primary native reads can hit OS page cache; disabled explicit application caches do not prove physical device reads.
* Acknowledgment differences matter: primary native explicit value-WAL barrier versus separate weaker page-cache cohort; Cassandra RF1 batch commitlog; TiKV 8.5.4 observed Raft config + source; FDB single durable log and transactional API; Valkey RAM + AOF always, with potential group commit. No fault-injection or physical-power-loss proof establishes interchangeable durability.
* Same RF1 count does not equal semantics, batch atomicity, transport security, data placement, CPU scheduling or caching. Do not assert unobserved TLS/auth settings for a backend; use experiment receipt. Compare the same API operation, payload, concurrency, outcome, timing boundary, and cache cohort; `get_many` calls vs logical keys and pipelining vs atomic batches are not interchangeable.
* Registered-RAM case is mixed: 2,372 RMA hits / 5,820 message fallbacks at 256 B; 2,361 / 5,831 at 8 KiB. Aggregate latency is not isolated one-sided wire latency. Raw probe itself includes provider completion and client validation, not a pure wire RTT. No external paper number is evidence of achievable G6 EFA performance.
* Tail samples do not establish independent-repeat variability; keep under-10,000 p99 and under-100,000 p99.9 sample warnings, and include rejections in admission analysis. OS cache drop cannot flush all process caches; no universal physical-NVMe cohort claim.
* Open: actual point-in-time engine/block cache occupancy and physical read bytes by store/case are not determined by these literature sources; exact TiKV embedded RocksDB version not established. Experiment is neither a production security comparison nor measured HA/failover. Lowest-cost resolution is audit existing per-case config and counters; a future isolated measurement would be a separate authorized experiment, not a retroactive claim.
